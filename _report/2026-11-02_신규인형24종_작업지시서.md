## 1. 목표
지금은 12종 인형(소~코끼리)을 **색만 바꿔 3바퀴 돌려쓴다** (1바퀴 원본, 2바퀴 파랑 `_b`, 3바퀴 빨강 `_r`).
**2바퀴(스테이지 13~24)와 3바퀴(25~36)를 새 동물 24종으로 바꿔 반복을 없앤다.**

**최우선 조건: 새 인형은 기존 12종과 "같은 세트"로 보여야 한다.** 따로 만든 것처럼 보이면 실패다 (아래 §3 합격 기준).

### 핵심 원칙 — 기존 동물 모양을 "확장"해서 만든다
- 새 동물은 **반드시 기존 12종 중 하나를 베이스로** 만든다. 몸통·머리·팔다리 비율과 자세는 베이스 인형을 그대로 따르고, 귀·뿔·꼬리·털·무늬·색 같은 **특징만 바꾸거나 덧붙인다**.
- 이유: **베이스 인형의 뼈대와 애니메이션 4종을 그대로 쓰기 위해서**다. 체형이 같아야 공격·대기·점프 움직임이 기존과 똑같이 자연스럽게 나온다.
- 베이스 1종당 파생 2종 → 12 × 2 = 24종. **2바퀴는 파생 A, 3바퀴는 파생 B** 로 배치해 스테이지 순서 구조(1바퀴 n번째 = 같은 베이스)를 유지한다.
- 베이스와 너무 달라서 뼈대를 공유할 수 없는 동물(예: 목이 긴 기린, 날개 큰 독수리)은 쓰지 않는다.

## 2. 진행 방식 — 반드시 "시범 2종 → PD 승인 → 나머지" 순서
1. **시범 단계**: 2종만 끝까지 만든다 (컨셉 → 3D → 뼈대·애니 → 게임 적용 → 비교 렌더).
2. **PD 승인**을 받는다. 불합격이면 원인과 대안(재생성, 방식 변경, 사람 3D 아티스트 외주)을 보고하고 멈춘다.
3. 승인 후 나머지 22종을 같은 방식으로 진행한다.

## 3. 합격 기준 ("느낌이 같다"의 정의)
기존 인형과 **같은 카메라·조명으로 나란히 렌더한 비교 이미지**로 판정한다. 아래가 모두 맞아야 한다.
- **재질**: 뜨개(니트) 인형 질감. 매끈한 플라스틱·도자기·실사 털이면 실패
- **비율**: 큰 머리 + 짧고 굵은 팔다리 + 통통한 몸통 (기존 12종과 같은 2~2.5등신 느낌)
- **얼굴**: 기존처럼 단순한 눈·코 (단추/자수 느낌). 사실적인 눈이면 실패
- **색감**: 기존 12종 팔레트 안의 파스텔/중간 채도. 형광색·과한 대비 금지
- **크기·실루엣**: 기계 안에 섞여 있을 때 한 종만 튀지 않을 것
- **게임 동작**: 집게로 잡히고, 대기·공격·점프 애니가 기존 인형과 같은 리듬으로 움직일 것
- 최종 판정은 PD. 비교 이미지와 게임 플레이 영상(또는 캡처)을 함께 제출한다.

## 5. 단계별 작업

### 5-1. 스타일 기준서
- 기존 12종을 정면·옆·3/4 각도로 같은 조명에서 렌더해 `D:\pick\_design\dolls\style_ref\` 에 저장.
- 비율·색·질감 요약을 `D:\pick\_design\dolls\style_guide.md` 에 정리. 이후 모든 비교의 기준.

### 5-2. 2D 컨셉 (외주 디자이너 Codex) — 베이스 인형 렌더를 고쳐 그리는 방식
- 의뢰 방법은 기존 예시를 따른다: `D:\pick\_design\의뢰_*.md` + `codex.exe exec ... -i <참고이미지>` (쓰기 허용 `D:\pick\_design\` 만).
- **베이스 인형의 정면·옆 렌더(5-1)를 첨부하고, "이 인형과 같은 자세·비율·크기에서 특징만 바꿔 ○○로 만들어라"** 로 의뢰한다. 처음부터 새로 그리게 하지 않는다.
- 동물마다 **정면 1장(필수) + 옆(권장)**, 투명 또는 단색 배경, 그림자 없는 균일 조명.
- 컨셉을 베이스 렌더 위에 겹쳐 봤을 때 **몸통·머리·팔다리 위치가 거의 겹쳐야** 한다 (뼈대 공유 조건). 안 겹치면 3D로 넘기지 않는다.
- §3 기준(비율·얼굴·색) 1차 확인도 이 단계에서 한다.

### 5-3. 3D 만들기 — 두 가지 방법 중 동물마다 선택
**방법 1 (우선 시도): 베이스 메시를 직접 고친다 (Blender)**
- 베이스 인형 FBX(뼈대·웨이트 포함)를 불러와 **메시 일부만 변형·추가**한다: 귀 모양 변경, 뿔·엄니·볏·꼬리 추가, 털 덩어리 추가 등. 새로 붙인 부위는 가까운 뼈에 웨이트를 준다.
- 텍스처는 베이스 텍스처를 바탕으로 색·무늬를 새로 칠한다 (디자이너 컨셉 기준, 뜨개 질감 유지).
- 뼈대·애니가 그대로 유지되므로 **움직임 일치가 가장 확실**하다. 변화가 "특징 추가 + 색 변경" 수준인 동물(양·염소·얼룩말·당나귀·북극곰·호랑이·치타·병아리·펭귄 등)은 이 방법을 먼저 쓴다.

**방법 2: Meshy 로 새 메시를 만든 뒤 베이스 뼈대에 입힌다** — 방법 1로 형태 차이를 감당하기 어려운 동물(거북이 등껍질, 해파리 갓, 하마 주둥이 등)에만.

#### Meshy API 사용법 (방법 2)
- **API 키는 환경 변수 `MESHY_API_KEY` 에서 읽는다. 파일·로그·커밋에 키를 절대 남기지 않는다.**
- 이미지→3D: `POST https://api.meshy.ai/openapi/v1/image-to-3d` (헤더 `Authorization: Bearer $MESHY_API_KEY`), 본문 `image_url` 에 컨셉 이미지 (공개 URL 또는 `data:image/png;base64,...`). 응답의 task id 로 `GET .../image-to-3d/{id}` 폴링 → `model_urls` 에서 FBX/GLB 다운로드. 옵션(텍스처 생성, 폴리곤 수 등)은 **작업 시점의 Meshy 공식 API 문서를 확인**해 정한다.
- 산출물은 `D:\pick\_design\dolls\meshy\<animal>\` 에 원본 그대로 보관 (재생성 이력 포함).
- 폴리곤 수는 기존 인형 수준으로 (기존 FBX 크기 약 120~240KB 참고). 너무 무거우면 디시메이트.
- 크레딧을 쓰므로 **같은 동물 재생성은 3회까지**. 넘으면 PD 에게 보고.

### 5-4. 뼈대·애니메이션 (베이스 인형 것을 그대로 재사용)
- 목표: 새 인형은 **매핑표의 베이스 인형 뼈대와 애니 4종(attack00 / idle00 / idle01 / jump00)을 그대로** 쓴다. 다른 베이스의 뼈대를 섞지 않는다.
- 방법 1은 뼈대가 이미 들어 있으므로 새 부위 웨이트만 확인한다. 방법 2는 아래처럼 베이스 뼈대에 스키닝한다.
- 애니 FBX 는 새로 만들지 않고, 새 인형의 overrideController 가 **베이스 인형의 애니 클립을 가리키게** 해도 된다 (뼈 이름·계층이 같을 때). 이 경우 애니 FBX 복제는 생략한다.
- 도구: **Blender 5.2.3 LTS** (설치됨: `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`, 백그라운드 실행 `blender.exe -b --factory-startup --python <script>`). 2026-11-02 확인: `doll_cow_full.FBX` 를 읽으면 뼈대 11개·메시 956정점·가중치 11그룹, `doll_cow_full_attack00.FBX` 는 같은 뼈대 11개 + 65프레임 액션으로 정상 임포트됨. 참고로 `doll_panda_full.FBX` 의 메시 이름은 `doll_bear_full` — 원 제작자도 곰을 확장해 판다를 만든 것. 스크립트로 기존 FBX 뼈대 불러오기 → 새 메시 정렬·스케일 → 자동 웨이트 → 귀·눈 등 보조 뼈는 가까운 부위에 연결 → FBX 내보내기.
- Meshy 자체 자동 리깅/애니는 **쓰지 않는다** (움직임 느낌이 기존과 달라짐). 단, 스키닝이 불가능하다고 판단되면 그 사실과 대안을 보고하고 멈춘다.

### 5-5. 게임 적용 (Unity)
새 키 `<key>` 마다:
1. FBX·애니 FBX·overrideController·머티리얼(기존 cow 머티리얼 복제 → 텍스처만 교체, `_FABRIC_SHEEN` 유지)·텍스처를 기존 명명 규칙(`doll_<key>_full*`)으로 추가. Import 설정은 기존 인형 FBX 와 동일하게.
2. 인형 프리팹: **같은 체형의 기존 프리팹을 복제**해서 모델만 교체 (`joint_anchor`/`headSocket`/`bottomSocket` 위치 재조정). 충돌체는 ConcaveCollider 로 새 메시 기준 재생성 — 물리재질 동일.
3. 보스 프리팹 `doll_<key>_mon_prefab`, 미션 아이콘 `<key>MissionIcon`, 썸네일 `<key>`·`<key>_boss` (기존 썸네일과 같은 구도·크기로 렌더 캡처).
4. `stringData.json` 에 `doll_name_<key>` 4개 언어 추가 (UTF-8, JSON 깨짐 확인).
5. 울음소리 `game_sounds/dolls/<key>_1.wav` — 저작권 안전한 소스만. 없으면 비슷한 기존 동물 소리를 임시 지정하고 보고.
6. `actor.json` 13~36행: `animalKey`·`nameKey`·`model`·`sound` 를 새 동물로 교체, `texture` 필드 삭제. **스탯·보상(ally*/boss*/clearCoinReward)은 지금 값 그대로 유지** (난이도 곡선 보존). `inGameScale`·`collectionScale` 은 기계 안·도감에서 기존 인형과 크기가 맞게 조정.
7. 황금 인형 효과(`GameDollCreator.ApplyGoldenMetal`)·도감(CollectionManager)·미션·랜덤박스에서 새 인형이 정상 표시되는지 확인.

### 5-6. 기존 세이브 처리 — **PD 결정 필요, 결정 전에는 구현하지 말 것**

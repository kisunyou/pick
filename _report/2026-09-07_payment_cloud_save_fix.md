# 결제 중복 지급·클라우드 복원 수정

대상: `D:\pick`, Android / Unity 6000.3.20f1. 개인정보처리방침·계정 삭제는 사용자가 별도 설정했다고 알려 수정 범위에서 제외했다.

## 변경한 동작

- 코인 잔액과 지급한 거래 ID를 `CoinWalletV2` 한 레코드에 함께 저장한다. 같은 거래 ID가 재전달되면 코인을 추가하지 않는다. 코인을 사용한 뒤 앱을 다시 실행해도 지급 이력이 유지된다.
- 기존 `ItemAmount_1` 코인은 최초 실행 시 새 지갑으로 이전한다. 기존 버전 1 클라우드 저장을 읽을 수 있으며, 새 저장은 버전 2 지갑을 포함한다. 손상된 거래 이력을 빈 이력으로 초기화하지 않는다.
- 상품 조회 후 미확정 주문을 명시적으로 조회한다. 거래 ID가 없거나 지원하지 않는 주문은 확정하지 않는다.
- 지급 결과와 거래 이력의 클라우드 저장이 성공한 뒤에만 Google Play 주문을 확정한다. 저장 실패 시 로컬 지급 기록을 유지하고 재시도 화면을 표시한다. 앱 종료 후에는 미확정 주문 재전달로 이어서 처리한다.
- 구매는 로그인과 클라우드 동기화가 완료된 상태에서 시작한다. 구매 요청·거래에 계정 ID를 연결해 같은 기기에서 다른 계정으로 잘못 지급하는 것을 방지한다.
- 로그인 복원에 제한 시간을 두고, 취소 시 요청과 코루틴을 중단한다. 세대 번호와 계정 ID가 달라진 응답을 무시한다. 로컬 플레이를 시작한 뒤 백그라운드 복원으로 데이터를 교체하지 않는다.
- 명시적 계정 전환 중에는 입력·물리·진행 중 애니메이션을 잠근다. 이전 계정의 보상 연출을 먼저 정산하고, 복원 후 전투·인형·미션·타이머 표시를 새 데이터로 갱신한다. 전환 복원 실패 시 재시도 화면을 유지한다.
- Firestore 저장에 서버 `updateTime` 선행 조건을 사용한다. 다른 기기의 최신 저장을 오래된 로컬 상태로 덮어쓰지 않는다. 저장 응답만 유실된 경우 서버 데이터를 조회해 해당 쓰기의 성공 여부를 확인한다.
- 한국어·영어·일본어·태국어 안내 문구를 추가하고 기존 게임 글꼴을 사용한다.

## 확인 결과

- Unity 회귀 검사 11개 통과: 재전달·재시작·사용 후 잔액 유지, 거래 ID 누락, 오버플로, 큰 잔액 직렬화, 버전 1 이전, 버전 2 거래 이력 필수, 클라우드 왕복 직렬화, 중복 필드 거부, 손상된 이력 거부, 계정 식별자 덮어쓰기 거부, 복원 취소와 늦은 응답 무효화.
- 에디터 메뉴: `Tools > Release Safety > Run regression checks` (Edit Mode 전용).
- Android 검증 빌드 성공, 빌드 오류 0개. 결과 파일: `build/pick_release_safety_validation.apk`.
- 검사 로그: `Logs/release_safety_result.txt`, `Logs/release_safety_build_result.txt`.

## 실제 서비스에서 추가로 확인할 항목

자동 검사는 로컬 데이터와 취소 로직을 검증했다. 실제 결제나 운영 Firebase 데이터를 생성·수정하는 테스트는 실행하지 않았다. Google Play 내부 테스트에서 다음 흐름을 확인해야 한다.

1. 결제 직후 앱 강제 종료 → 재실행 → 코인이 한 번만 지급되는지 확인.
2. 지급 후 주문 확정 전에 통신 차단 → 재시도/재실행 → 추가 지급 없이 확정되는지 확인.
3. 느린 로그인 복원 → 로컬 게임 시작 → 늦은 응답이 진행을 바꾸지 않는지 확인.
4. 기존 Google 계정으로 전환 → 복원 실패/재시도 → 계정 데이터와 화면이 일치하는지 확인.
5. 두 기기에서 같은 계정 사용 → 오래된 기기가 최신 저장을 덮어쓰지 않는지 확인.

동기화 실패 후 로컬 플레이를 시작한 세션에서는 안전을 위해 구매를 제한하며, 정상적인 복원은 앱 재시작으로 다시 시도한다. 다른 기기와 저장 충돌이 감지된 경우에도 자동 병합 없이 재시작을 안내한다.

이 수정은 기존 클라이언트·Firestore 저장 구조 안에서 재전달과 복원 경합을 방어한다. 서버 영수증 검증, 서로 다른 Firebase 계정/재설치 기기 전체에 걸친 거래 소유권 보장은 별도 서버 구현이 필요하다. 이미 지급했으나 거래 이력을 남기지 않은 구버전 주문의 지급 여부는 소급 판별할 수 없다. 구버전 앱이 새 저장을 덮어쓰지 않도록 배포 시 구버전 사용 제한도 확인해야 한다.
